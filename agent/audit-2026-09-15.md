## 範圍與方法

## 確認缺陷與 RED → GREEN

| 行為 | 修正前的失敗證據 | 修正及測試 |
| --- | --- | --- |

| SQLite URL 邊界 | 接受尾端空 query `?` 或編碼 NUL 路徑 | 明確拒絕；同時驗證 opaque 相對路徑仍拒絕；`store/audit_test.go` |

| HTTPS 反代 Cookie | 內部 HTTP 轉送、外部 HTTPS Origin 的登入 Cookie 缺少 Secure | 使用已驗證同 Host 的 HTTPS Origin；不直接信任 X-Forwarded-*；`TestHTTPSProxyLoginUsesSecureCookie` |

## 新增檢查但未發現缺陷

- 私人模式 10 條 API：無 Session／超過 24 小時 Session 均拒絕，包含設定、主機、歷史、告警、Token 與資料庫操作。
- 通知 307 重新導向：只送一次請求，不向另一個主機轉送事件，也不在錯誤中輸出私密 URL。
- 搬移中途失敗：在已寫入 node/sample 之後，以目標 SQLite trigger 拒絕 alert；整筆交易回滾，目標沒有部分主機、歷史、告警、通知或 marker，來源 Token hash 保持完整。
- 既有樣本速率、計數器重設、歷史分桶、通知重試、搬移重試與採集取消的回歸均通過。

這些檢查首次即通過，沒有杜撰 RED 或修改已正常的行為。

## 限制與清理

- PostgreSQL 真實雙向搬移、完整 HTTP race、ARM64 真機、正式 systemd／TLS 反代、外部 Telegram／Webhook、長期多機負載仍待對應環境驗證。
- API 仍以單主程式共享鎖與單資料庫連線維護一致性；本次排除明確的慢 body、大回應與 bcrypt 阻塞，沒有宣稱已完成高併發壓測。
- Agent 斷線不補傳，通知可能重送，告警摘要依最近 100 個事件計算，沿用原需求與已記錄使用邊界。
- 瀏覽器使用隔離暫存資料及 180 秒 TTL fixture；一般啟動方式受 shell 超時終止後，改用 detached 子程序並保留 finally／TTL 清理。瀏覽器驗證完成後已關閉頁面；最終 Windows 程序查詢與 WSL pgrep 均沒有本次 fixture／server／agent 殘留。
